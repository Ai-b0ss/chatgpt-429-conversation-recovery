# ChatGPT Conversation Availability Guard — «Этот чат недоступен» и HTTP 429

Неофициальное расширение для устойчивости загрузки разговоров ChatGPT и диагностики случаев, когда из-за HTTP 429 появляется «Этот чат недоступен».

**Последний опубликованный релиз:** ChatGPT 429 Guard v0.8.4.
**Текущий development candidate:** Conversation Availability Guard v0.9.3.

v0.8.4 действительно уменьшал повторные запросы и проходил синтетические сценарии восстановления, но он **не предотвратил реальный подтверждённый повторный сбой**. 5 октября 2026 production-тест на chatgpt.com зафиксировал точную цепочку: GET conversation-detail начал получать настоящий HTTP 429 без Retry-After; старый короткий бюджет выдал 429-final примерно через 6 секунд, а сервер оставался rate-limited около 2,5 минуты. Именно после раннего 429 интерфейс мог зафиксироваться в состоянии «Не удалось загрузить этот разговор ChatGPT».

v0.9.3 сохраняет безопасный production GET conversation-detail в recovery-режиме до 5 минут с редким возрастающим backoff, вместо того чтобы отдавать transient 429 React. Локальная v0.9.0 resume-recovery и защита stream_status при этом сохраняются.

Расширение **не обходит лимиты OpenAI и не увеличивает лимиты подписки**. Оно уменьшает лишний retry-storm, соблюдает Retry-After и удерживает безопасный GET до восстановления сервера в ограниченном временном окне.

## Что v0.9.3 защищает активно

Автоматические retry/dedupe применяются только к безопасным GET:

- GET /backend-api/conversations/{id}
- GET /backend-api/conversation/{id}
- GET /backend-api/conversation/{id}/stream_status
- GET /backend-api/conversations

Активная 429-защита stream_status — новое покрытие v0.9.3. Локальная v0.9.0 уже наблюдала stream_status для resume-recovery, но базовый 429 Guard по-прежнему пропускал 429 на этом GET без retry.

Связанные POST:

- POST /backend-api/f/conversation/resume
- POST /backend-api/conversations/batch
- POST /backend-api/conversation/init

только наблюдаются. Автоматически повторять их нельзя, пока не доказана идемпотентность: иначе можно задублировать действие.

Отправка сообщений, загрузка файлов, модельные запросы и другой несвязанный трафик не меняются.

## Диагностика

Popup теперь хранит и копирует ограниченную историю последних безопасных событий. Для каждого сбоя важны:

- поверхность: conversation-detail, stream-status, conversation-resume и т. п.;
- HTTP method/status;
- была ли защита active или запрос только наблюдался;
- попытка, задержка и Retry-After, если они есть;
- время события.

В storage/экспорт не должны попадать текст разговоров, cookies, Authorization, body запросов/ответов, полный URL, ID разговора, tab ID или correlation hash.

Если «Этот чат недоступен» повторится, лучше сразу нажать **Copy safe diagnostics** до долгого дальнейшего использования вкладки.

## Проверенные локальные сценарии v0.9.3

В deterministic Playwright-тесте:

- stream_status получает 429;
- Guard удерживает ошибку внутри recovery-механизма;
- второй сетевой запрос получает 200;
- итоговый вызов для страницы возвращает 200;
- POST resume/batch/init при 429 выполняются только один раз;
- privacy-check подтверждает отсутствие идентификаторов в сохранённых событиях.

Это локальная проверка механизма, а не доказательство, что любой production-429 теперь исправлен.

## Установка

Для опубликованной версии:

1. скачайте ZIP из Releases;
2. распакуйте его в постоянную папку;
3. откройте chrome://extensions;
4. включите «Режим разработчика»;
5. нажмите «Загрузить распакованное расширение»;
6. выберите папку extension;
7. перезагрузите вкладки ChatGPT.

v0.9.3 пока нельзя называть стабильным релизом до его публикации и прохождения обоих regression-наборов.

## Ветки

- main — опубликованное стабильное состояние;
- 429-only — узкая ветка восстановления HTTP 429;
- maintenance/investigation branches — проверка следующих изменений.

Сам GitHub-репозиторий пока называется chatgpt-stream-recovery, но пользовательское название расширения меняется на **ChatGPT Conversation Availability Guard**, потому что задача шире обычного stream recovery.

Проект неофициальный и не связан с OpenAI.
